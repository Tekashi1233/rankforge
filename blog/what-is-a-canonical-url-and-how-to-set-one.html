What Is a Canonical URL and How to Set One

A canonical URL tells search engines which version of a page is the “real” one when the same content can be reached at more than one address. Setting it correctly stops duplicate URLs from splitting your rankings.

What a canonical URL means

Most pages can be opened at several addresses without you noticing: with and without www, over http and https, with a trailing slash or without, with tracking parameters like ?utm_source=newsletter attached, or in upper and lower case. To a visitor these are all the same page. To a search engine they are different URLs that happen to show the same content.

The canonical URL is the single address you want search engines to treat as the original. You declare it with a link tag in the page head:

<link rel="canonical" href="https://example.com/blog/my-post">

Every duplicate version of the page should carry the same tag pointing at that one preferred address.

Why it matters for SEO and GEO

When the same content lives at five URLs, links and signals get spread across all five instead of concentrating on one. Search engines may pick a version you did not intend, index the one with tracking parameters, or waste crawl budget re-crawling copies. A canonical tag consolidates those signals and makes the preferred URL the one that shows up in results.

AI answer engines face the same problem. If a model sees the same passage at several addresses, it has to guess which one to cite. A clear canonical gives it a single, stable URL to attribute, which is exactly what you want for citations.

How to choose the canonical version

Pick one convention and apply it everywhere. The usual choices are:

  • HTTPS, not HTTP.
  • One hostname: either www.example.com or example.com, never both.
  • Lowercase paths, since many servers treat /Blog and /blog as different URLs.
  • A trailing-slash rule: either always or never on non-homepage URLs.
  • No tracking parameters such as utm_*, fbclid or gclid. Keep parameters only when they change the content, like a product variant.

How to set a canonical tag

  1. Decide the preferred URL for the page using the rules above.
  2. Add <link rel="canonical" href="..."> inside the <head> with the full absolute URL, including https:// and the hostname.
  3. Use a self-referencing canonical on the preferred page itself. It is best practice even when you have no known duplicates.
  4. Make every duplicate version point to the same preferred URL, not to itself.
  5. Where possible, also redirect the non-preferred versions (http, www, trailing slash) to the canonical with a 301, so visitors and crawlers land on the right address in one hop.

Most CMS platforms add a self-referencing canonical automatically, but it is worth checking the page source, because themes and plugins sometimes emit the wrong hostname or a relative path.

Common canonical mistakes

  • Relative URLs like href="/blog/my-post". Use the full absolute URL.
  • Pointing every page to the homepage. Each page needs its own canonical.
  • Mixing conventions, such as a canonical with a trailing slash on one page and without on the next.
  • Canonical and redirect disagreeing. If page A canonicalises to B but B redirects to A, search engines will ignore both.
  • Canonicalising paginated or filtered pages to page one when the content is genuinely different.
  • Canonical chains. If page A points to B and B points to C, search engines may stop following the chain and pick a version themselves. Point A straight at C.
  • Canonical pointing at a dead or redirected URL. A canonical that targets a 404 page, or a URL that redirects somewhere else, gets ignored. The target must return a 200 status and be the final address.
  • Conflicting with hreflang. Each language version should usually be its own canonical.

How to check your canonical

View the page source and search for rel="canonical". Confirm it is absolute, uses HTTPS and your preferred hostname, and matches the URL you actually want indexed. The most common duplicate-URL situations

Duplicates rarely come from copying a page on purpose. They usually appear because a site serves the same content at several addresses without anyone noticing. These are the ones to watch for:

  • Trailing slash. /blog/my-post and /blog/my-post/ are different URLs. Pick one form and canonicalise the other to it.
  • www and http versions. http://example.com, https://www.example.com and https://example.com can all serve the same page. Canonicalise them all to the one version you chose — usually the HTTPS address without www.
  • Tracking parameters. A link shared in a newsletter adds ?utm_source=newsletter to the URL. The page is the same, so the tracked version should canonicalise to the clean URL.
  • Sort and filter parameters. A category page with ?sort=price or ?colour=blue shows the same products in a different order. Canonicalise those variants to the plain category page — unless a filtered view is a page you genuinely want ranked on its own.
  • Print and PDF versions. A printer-friendly page or a PDF of the same article is a copy. Point its canonical at the normal web page.
  • Product variants. A product in three colours may live at three URLs. Canonicalise the variants to the main product page, or give each variant its own self-referencing canonical if you want every colour indexed separately.

The rule behind all of these is the same: the canonical should point at the version you would share with someone if you could only share one link.

Canonical vs redirect vs noindex: which one to use

Three tools solve three different problems, and mixing them up is a common mistake.

  • 301 redirect — use it when a URL should never be visited again: a page moved, a duplicate you want gone, an old address replaced by a new one. A redirect is an instruction, and it also sends visitors to the right place.
  • Canonical tag — use it when both URLs need to stay live: tracking links, a print version, a product reached through several category paths. A canonical is a hint, not an order, so Google can still choose differently.
  • Noindex — use it when a page is useful to visitors but should never appear in search results: internal search pages, login pages, thank-you pages after a purchase. A noindex page is still crawled; it just is not shown in results.

Do not stack them carelessly. A page that is noindexed should not also canonicalise to another page and expect its ranking signals to move — search engines are likely to ignore the canonical on a page they are told not to index. Pick one tool per job: redirect to remove, canonical to consolidate, noindex to hide.

How to check Google actually honoured your canonical

A canonical tag is a hint, so Google sometimes picks a different URL. Check whether it listened in Search Console: open the URL Inspection tool, enter the page, and compare the "User-declared canonical" with the "Google-selected canonical". If they match, the canonical is working. If they differ, something is off — common causes are a canonical pointing at a page that redirects or returns a 404, a canonical placed in the page body instead of the head, or two pages whose content is so different that Google treats them as separate pages rather than duplicates.

For a whole-site view, use the Page indexing report and look for "Duplicate, Google chose different canonical than user" and "Duplicate without user-selected canonical". The first means your tag was seen but overruled; the second means Google found duplicates you never marked. Fix the first group by checking the canonical target is live and matches the content; fix the second by adding canonicals to the duplicates Google found.

Quick fix checklist

  1. Choose HTTPS, one hostname, lowercase paths and a trailing-slash rule.
  2. Add an absolute self-referencing canonical to every indexable page.
  3. Point all duplicate versions at that one URL.
  4. Redirect http, www and trailing-slash variants with a 301.
  5. Re-check the source after any theme or plugin change.

A correct canonical is one of the cheapest technical fixes in SEO: one line in the head, and every signal your page earns lands in the same place.

Frequently asked questions

Can a page have more than one canonical tag?

No — use exactly one. If a page carries two canonical tags, search engines pick one themselves and may ignore both, so check your theme, plugins and templates for duplicates after every change.

Should the canonical point to the page itself?

Yes. Every indexable page should carry a self-referencing canonical: an absolute URL pointing at its own preferred address, even when no duplicate versions exist. It confirms to search engines that this URL is the one to index.

Does a canonical tag replace a redirect?

No. A canonical is a hint, while a 301 redirect is a firm instruction. Use a redirect when a duplicate URL should never be visited, and a canonical when both versions need to stay live — for example, a product page reached through several category paths.
