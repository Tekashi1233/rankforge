Why heading structure matters

Headings (H1 through H6) create the outline of a page. Search engines and AI systems use that outline to understand topics and subtopics. Screen readers rely on it for navigation. A clear hierarchy also helps human readers scan the page.

The outline also shapes how a page is found and quoted. Search engines use headings to work out what each section is about, and answer engines do the same when they pull a passage into a result. A page with clear, descriptive headings is easier to summarise and easier to link to, because each section has a name. None of this needs clever wording: headings that plainly state what the section covers do the job better than headings written to sound impressive.

Common problems this tool catches

  • Missing H1 — every page should have exactly one main H1 that states the primary topic.
  • Multiple H1s — can dilute the main topic signal.
  • Skipped levels — jumping from H1 to H3 (or H2 to H4) without the intermediate level confuses both users and machines.
  • Out-of-order levels — headings that decrease then increase inconsistently.

Fixing these issues is one of the simplest on-page SEO and accessibility wins you can make.

How to use this Heading Structure Checker

  1. Paste the page HTML into the box, or paste plain text that uses Markdown-style headings (# for H1, ## for H2, and so on).
  2. Click Analyse headings. The checker lists every heading in order, counts the H1 tags, and flags skipped levels.
  3. Fix the flagged issues first: add a missing H1, remove extra H1 tags, then fill in any skipped levels.
  4. Paste the updated HTML and analyse it again to confirm the outline is clean.

A worked example: fixing a messy outline

Here is an outline the checker might flag on a recipe page, with the problems marked:

H1: The Best Chocolate Cake
H3: Ingredients
H3: Method
H2: Why this cake works
H4: Storage tips

The ingredients and method sections jump straight from H1 to H3, skipping H2, and the storage tips jump from H2 to H4. The fix keeps the same words and only changes the levels:

H1: The Best Chocolate Cake
H2: Ingredients
H2: Method
H2: Why this cake works
H3: Storage tips

Nothing about the page looks different to a reader, because the visual size of a heading is set by styling, not by its level. But the outline now reads as a clean list: one main topic, three sections, and a subsection where it belongs. Run the checker again after the fix to confirm the flags are gone.

Headings are not for styling

A common habit is picking a heading level because of how it looks: H3 because it is smaller than H2, or H4 because it fits neatly in a sidebar. That ties the page structure to the design, and it breaks the outline. The level should always follow the structure: a section gets H2, a subsection of that section gets H3, and so on. If an H2 looks too big, change its size in CSS. The heading level describes meaning, and the stylesheet describes appearance. Keeping the two separate is what makes the outline reliable for search engines and screen readers.

How to write good heading text

  • Say what the section is about in plain words. "How to check your outline" beats "A few thoughts".
  • Keep headings short enough to scan, usually one line. A heading that wraps to three lines is doing the paragraph's job.
  • Use the words your readers use. If people search for "how to fix skipped heading levels", a heading with those words in it helps them find the section.
  • Do not stuff keywords into every heading. One clear, honest heading per section is enough, and a page full of repeated phrases reads badly.
  • Avoid headings that only make sense in context, like "More" or "Next steps", when the section could name itself. A reader who jumps straight to that section should know what it covers.

Good headings work twice: they help a reader who is scanning the page, and they help a search engine that is building a picture of what the page covers.

Common heading mistakes on real sites

  • Using the logo or site name as the H1 on every page. The H1 should describe the page, not the site.
  • Putting the main keyword in an H2 and leaving the H1 vague. The strongest signal on the page should carry the clearest description of the topic.
  • Splitting one topic across several H2s with the same text. Two sections both headed "Features" tell a reader nothing about how they differ.
  • Using bold paragraphs instead of headings. Bold text looks like a heading, but screen readers and search engines cannot see it as one.
  • Nesting headings for visual indentation. Indenting a section is a styling choice; it does not make the section a subsection.

Frequently asked questions

How many H1 tags should a page have?

Exactly one. The H1 should state the main topic of the page and usually matches the title tag. Extra H1 tags dilute that signal, so demote styling-only headings to H2 or lower.

Does skipping a heading level hurt SEO?

It can. A jump such as H1 straight to H3 breaks the page outline, which makes the topic structure harder for search engines, AI answer engines and screen readers to follow. Add the missing level instead of skipping it.

Can I check Markdown headings as well as HTML?

Yes. If no HTML headings are found, the checker reads Markdown-style headings instead: one hash (#) is H1, two hashes (##) are H2, and so on up to six hashes.

What should I fix first?

Start with the H1: add one if it is missing, or keep only one if there are several. Then fix skipped levels, working from the top of the page down, and re-check the outline after each edit.

Should every page have an H2?

Most pages should. If a page has only an H1 and long paragraphs, splitting the content into H2 sections makes it easier to scan and gives search engines a clearer outline. Very short pages may not need one.

Do headings directly affect rankings?

Headings are a small part of how search engines understand a page, not a ranking trick on their own. Clear headings help because they make the topic structure obvious, but they will not rescue thin or unhelpful content.
