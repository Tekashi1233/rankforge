What is a canonical URL?

A canonical URL is the preferred version of a page that you want search engines to index when the same content is available at more than one address. You declare it with a <link rel="canonical" href="…"> tag in the page’s <head>. Google and other engines usually honour the tag, consolidating ranking signals onto the single preferred URL instead of splitting them across duplicates.

Common duplicate situations include HTTP vs HTTPS, www vs non-www, trailing-slash variants, session IDs, and tracking parameters such as utm_source or fbclid. Without a clear canonical, search engines may treat those versions as separate pages, diluting authority and wasting crawl budget.

Why a clean self-referencing canonical matters

Every page should point its canonical to itself (a self-referencing canonical). This removes ambiguity even when you do not currently have duplicates. It also protects against future issues if someone links to the page with extra parameters. Consistent canonicals make it easier for search engines and AI systems to understand which URL is the authoritative one.

Normalization rules used by this tool follow common SEO practice:

  • Prefer HTTPS over HTTP.
  • Use consistent casing (usually lowercase).
  • Remove tracking and advertising parameters that do not change page content.
  • Decide on a trailing-slash policy and stick to it.

Canonical tags also matter in places people forget about. Print-friendly pages, PDF versions of articles, and pages reached through site search can all end up indexed as separate pages with the same content. So can the www and non-www versions of a site, and the HTTP and HTTPS versions. A self-referencing canonical on the preferred version, plus the same canonical on every duplicate version, ties all of them together. It does not delete the duplicates or stop people visiting them. It tells search engines which address should carry the ranking signals, which is usually all you need.

Best practices for canonical tags

  • Use absolute URLs (include https://).
  • Point to a page that returns HTTP 200, not a redirect or error.
  • Include a self-referencing canonical on the preferred page itself.
  • Be consistent: every duplicate should point to the same preferred URL.
  • When using hreflang, the canonical should usually be the same-language version.
  • Do not rely on robots.txt or noindex alone to solve duplicate-content problems.

A worked example: one product, four URLs

Imagine a running shoe page that shoppers can reach four ways:

  • https://example.com/products/blue-running-shoes
  • https://example.com/products/blue-running-shoes?color=blue
  • https://example.com/products/blue-running-shoes?utm_source=newsletter
  • https://example.com/products/BLUE-running-shoes

All four show the same shoe. Without a canonical, a search engine has to guess which one is the real page, and links pointing at the different versions split their value four ways. The fix is one clean address, https://example.com/products/blue-running-shoes, with the same tag on all four versions:

<link rel="canonical" href="https://example.com/products/blue-running-shoes">

Note that the colour parameter stays out of the canonical even though it describes the shoe, because the page content is the same with or without it. If the colour parameter showed a genuinely different product, a different shoe with its own price and photos, then it would deserve its own canonical instead.

Canonical tags vs 301 redirects vs noindex

These three tools solve overlapping problems, and picking the wrong one is a common source of trouble. Use a canonical tag when both versions of a page should stay live and reachable, but only one should collect ranking signals. Tracking links, print views, and sort orders are typical cases. Use a 301 redirect when the old URL should no longer exist at all, for example after a page moves or two pages merge into one. Visitors and crawlers land on the new address. Use noindex when a page should stay live for visitors but stay out of search results, for example an internal search page or a thank-you page after checkout. Do not mix the signals: a canonical that points at a noindex page, or a noindex page that canonicals to itself, tells search engines two different things at once. Pick the outcome you want first, then use the one tool that matches it.

Common canonical mistakes

  • Pointing the canonical at a redirect. If the preferred URL redirects somewhere else, the canonical is really pointing at that final page. Point it there directly.
  • Using relative URLs. A canonical of /blog/post can be misread if the page is served on more than one host or protocol. Always use the full absolute URL starting with https://.
  • Canonicalising every page to the homepage. This is a shortcut some templates take, and it is wrong. It tells search engines that only the homepage should be indexed, which can push real pages out of the results.
  • Two canonical tags on one page. Templates and plugins sometimes each add one. Search engines may then ignore both. Check the rendered page source and keep exactly one.
  • Canonical chains. Page A points to page B, and page B points to page C. Each hop weakens the signal. Point every duplicate straight at the final preferred URL.
  • Pointing at a page that returns an error. A canonical to a 404 or a blocked page is a dead end. The preferred URL must return a normal 200 response and be indexable.

Frequently asked questions

Does every page need a canonical tag?

Yes. A self-referencing canonical is best practice even when you have no known duplicates. It removes ambiguity for search engines.

Should I strip all query parameters?

Only tracking and advertising parameters that do not change the page content (utm_*, fbclid, gclid, etc.). Keep parameters that actually select different content, such as product variants or pagination if those are distinct pages.

HTTP or HTTPS in the canonical?

Always prefer the HTTPS version unless your site has a technical reason to stay on HTTP.

What about trailing slashes?

Pick one convention (with or without) and apply it consistently. This tool lets you remove trailing slashes on non-homepage URLs if that is your preference.

Can a page have more than one canonical tag?

No. A page should have exactly one canonical tag. If a template and a plugin each add one, search engines may ignore both. Check the rendered page source, remove the duplicate, and keep the one that points at the correct preferred URL.

Will Google always follow my canonical tag?

Not always. A canonical tag is a strong hint, not a direct order. Google usually follows it, but it may pick a different URL if other signals disagree, for example if the canonical points at a redirect or a page that is blocked. Check Search Console to see which URL Google actually indexed.
