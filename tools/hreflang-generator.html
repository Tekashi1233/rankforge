Hreflang Tag Generator

Create alternate link tags for the language and regional versions of a page. Everything is generated in your browser; your URLs are not uploaded.

Use language codes such as en, en-US or fr-CA. Enter the full canonical URL for each page.

What hreflang tags do

Hreflang annotations help search engines understand which pages are language or regional alternatives. For example, a site might have separate pages for English speakers in the United States and the United Kingdom. The tags identify those relationships; they do not translate the content or guarantee that a search engine will show a particular version.

Without hreflang, a search engine may show the wrong version to the wrong audience: a Spanish speaker in Mexico sees the Spain Spanish page, or a Canadian visitor lands on the US English page with prices in dollars. Hreflang does not force a result, it is only a hint, but a correct hint means the right version usually wins. It also helps search engines understand that the pages are alternates, not duplicate content competing with each other.

How to use this generator

  1. Enter a valid language tag and the canonical URL for each version.
  2. Add every translated or region-specific page that should be an alternate.
  3. Optionally include an x-default URL for a fallback page.
  4. Generate and copy the tags into the <head> section of every listed page.

Each version should contain the same set of alternate links, including a link to itself, and every alternate page should link back. Use fully qualified HTTPS URLs when the pages support HTTPS. Choose language-region codes that match the actual content and audience, such as en-GB for British English or pt-BR for Brazilian Portuguese. A language-only code like fr is appropriate when the page targets French speakers across regions.

Check the implementation before publishing

After adding the tags, verify that every URL returns the intended page, that the language codes are correct, and that all versions reference one another. Keep canonical tags consistent with your preferred page URLs. Hreflang and canonical signals solve different problems, so neither should accidentally point all language versions to a single page.

A worked example: one product page in three markets

Imagine a shop sells a jacket and has one product page in English for the United States, one in English for the United Kingdom, and one in French for Canada. Each of the three pages should carry the same three tags, including a link to itself:

<link rel="alternate" hreflang="en-US" href="https://example.com/us/jacket" />
<link rel="alternate" hreflang="en-GB" href="https://example.com/uk/jacket" />
<link rel="alternate" hreflang="fr-CA" href="https://example.com/ca/fr/veste" />

The US page links to all three, the UK page links to all three, and the French Canadian page links to all three. If a fourth version is added later, for example German for Germany, all four pages need the new tag. That is the part people forget: hreflang is a set, and every page in the set must carry the full set.

Language codes that trip people up

Hreflang uses language tags, and small mistakes in them are common. A few to watch for:

  • Use en-GB for British English, not en-UK. The region part is a country code, and the code for the United Kingdom is GB.
  • Use pt-BR for Brazilian Portuguese and pt-PT for European Portuguese. Plain pt is fine when the page targets Portuguese speakers generally.
  • Chinese needs a script code: zh-Hans for simplified characters and zh-Hant for traditional characters. Plain zh leaves the search engine guessing.
  • Spanish for Latin America is es-419, a region code that covers the whole area, rather than a single country code.
  • Language codes are lowercase and region codes are uppercase by convention, as in fr-CA. Search engines are usually forgiving about case, but matching the convention keeps things clean.

If you are unsure about a code, check the page itself: the code should describe the language the page is actually written in and the audience it is actually for, not the country where the server sits.

Common hreflang mistakes

  • Only linking one way. Page A lists page B as an alternate, but page B does not list page A. Search engines may ignore the whole set when links do not go both ways.
  • Pointing hreflang at redirected or broken URLs. Every URL in the set should return a 200 status and the page it claims to be.
  • Using hreflang on pages that are not real alternates. A blog post and a product page in different languages are not alternates; translated versions of the same content are.
  • Mixing up hreflang and canonical tags. The canonical tag on each version should point to itself, or to that version's preferred URL, not to the English version. Sending every version's canonical to one page tells search engines the other versions do not matter.
  • Forgetting x-default or pointing it at the wrong page. The fallback should be a page that helps any visitor, such as a language selector, not a random product page.

Hreflang, canonical tags and sitemaps

Hreflang can also live in your XML sitemap instead of on the page, which suits large sites with many language versions. Either way works, but do not do both for the same pages, since keeping two copies in sync is how mistakes creep in. Whichever method you choose, keep the canonical tags consistent: each language version is canonical to itself. Hreflang says "this is the same content in another language", canonical says "this is the preferred URL for this content", and the two signals should never contradict each other.

Frequently asked questions

Do hreflang tags need to be reciprocal?

Yes. Each page should reference itself and all its alternates, and those alternate pages should include a link back. This generator creates one set of tags; use that same set on every page in the group.

What does x-default mean?

It can point to a fallback page for visitors whose language is not covered, often a language selector or a general-language landing page. It is optional.

Where should I place these tags?

For this HTML output, place the link elements in the head of each page. Keep the values identical across versions and ensure each referenced URL is accessible.

Do I need hreflang if my site has only one language?

No. Hreflang is only for pages that exist in more than one language or regional version. A single-language site has nothing to annotate.

Can I put hreflang in the sitemap instead of the page?

Yes. Search engines accept hreflang in an XML sitemap as well as in the page head. Pick one method for each set of pages and keep it consistent.
