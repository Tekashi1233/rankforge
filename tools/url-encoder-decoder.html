How to use this URL encoder

Paste or type any text or URL into the box. Pick a mode and the result updates as you type. Use "Encode text for a URL" when you have one value to put inside a link, such as a search term. Use "Encode a whole URL" when you have a full address and only want the unsafe parts fixed. Use "Decode" when someone sends you a link full of %20 and %D8 codes and you want to read what it actually says. Copy the result with one click.

What is percent-encoding?

A URL can only contain a limited set of characters safely. Everything else has to be written as a percent sign followed by two hexadecimal digits, like %20 for a space. Letters and digits from other alphabets are first turned into UTF-8 bytes, then each byte is written the same way. That is why the Arabic word السلام becomes %D8%A7%D9%84%D8%B3%D9%84%D8%A7%D9%85. The characters A-Z, a-z, 0-9 and - _ . ~ are never encoded.

encodeURI vs encodeURIComponent

JavaScript has two built-in functions for this, and picking the wrong one is the most common mistake. The table below shows the difference.

FunctionLeaves aloneUse it for
encodeURI; , / ? : @ & = + $ - _ . ! ~ * ' ( ) #A whole URL. It keeps the structure (://, ?, &) intact and only encodes the unsafe parts.
encodeURIComponentA-Z a-z 0-9 - _ . ! ~ * ' ( )One value inside a URL, such as a search term or a path segment. It encodes ?, &, = and # too, so they cannot break the link.

Run encodeURIComponent on a whole URL and it will encode the :// and the ?, which breaks the address. Run encodeURI on a search term that contains an & and the & stays, which splits your value into two parameters. When in doubt, encode each value separately and join them yourself.

Why it matters

Links break quietly. A space in a pasted URL can cut the link off at the space, so the person who clicks it lands on the wrong page or a 404. An & inside a search term can split one value into two parameters and change what the page shows. Non-English text in a link can arrive as a wall of percent codes that no one can read or trust. Encoding fixes all three before the link is shared. It also keeps analytics clean, because an unencoded space or bracket can make the same page show up as two different URLs in your reports.

A worked example: building a search link

Say you want to link to a search for "coffee shops in Riyadh" on example.com, with the language set to Arabic. The plain link looks like this: https://example.com/search?q=coffee shops in Riyadh&lang=ar. It has two problems. The spaces break the link, and the ampersand is fine here because it separates the two parameters, but a space inside the value would cut it short. Encode just the search value with encodeURIComponent and it becomes coffee%20shops%20in%20Riyadh. Now join the pieces yourself: https://example.com/search?q=coffee%20shops%20in%20Riyadh&lang=ar. The structure stays intact, the value is safe, and anyone who clicks the link lands on the right search. If the search term itself contained an ampersand, for example "fish & chips", encoding the value would turn it into fish%20%26%20chips, so the ampersand could not split the value into two parameters. That is the core habit: encode values, not whole URLs, and join the parts yourself.

Which characters must be encoded, and which can stay

URLs divide characters into three groups. Unreserved characters never need encoding: letters, digits, and - _ . ~. Reserved characters have a job in the URL structure, so they stay as they are when they are doing that job, but must be encoded when they appear inside a value: : / ? # [ ] @ ! $ & ' ( ) * + , ; =. Everything else, including spaces, angle brackets, curly braces, quotes, backslashes, non-English letters, and emoji, must be encoded. A space becomes %20 in a path, and %20 or + in a query string. The hash sign # is a special case: everything after it is a fragment that the browser keeps and never sends to the server, so a # inside a value has to be encoded as %23 or it will cut your value short. When you are unsure about a character, encode it. An encoded character that did not need encoding still works, while a character that needed encoding and did not get it breaks the link.

Common mistakes to avoid

  • Encoding a whole URL with encodeURIComponent, which encodes the :// and ? and breaks the address. Use encodeURI for a whole URL, or encode each value separately.
  • Encoding a value with encodeURI, which leaves & and = untouched, so they split your value into extra parameters.
  • Double encoding: encoding text that is already encoded, so %20 becomes %2520. Decode once first, then encode once.
  • Using a plain + for a plus sign in a query string. Servers read + as a space, so a real plus has to be %2B.
  • Forgetting the fragment: a # in a value must be %23, or everything after it is treated as a page anchor.
  • Pasting a URL with spaces into an email or document and trusting the reader's software to fix it. Encode before you share.

Encoding in everyday work

URL encoding shows up far beyond web development. Marketers encode UTM parameters so campaign names with spaces and ampersands survive in analytics. Support teams encode file names with spaces before sending download links, so the link does not stop at the first space. Anyone sharing a link to a page with an Arabic or accented title has to encode it, or the link arrives as a wall of percent codes that looks broken and untrustworthy. It also matters for QR codes: a QR code that holds an unencoded URL with a space may scan to a truncated address. A few seconds of encoding before sharing saves the confused reply, the broken link, and the lost visitor.

Frequently asked questions

What does a URL encoder do?

It replaces characters that are not safe in a URL with a percent sign and two hexadecimal digits. A space becomes %20, an ampersand becomes %26, and non-English letters become a sequence of percent codes. A decoder reverses the process.

When should I encode a URL?

Encode when a link contains spaces, non-English letters, emoji, or characters like &, ? and # inside a value. You do not need to encode a plain address made only of letters, digits, hyphens and slashes.

What is the difference between encodeURI and encodeURIComponent?

encodeURI encodes a whole URL and leaves its structure alone, so ://, ? and & stay as they are. encodeURIComponent encodes one value inside a URL and escapes those characters too, so they cannot break the link apart.

Why did my %20 turn into %2520?

That is double encoding. The text was already encoded, and encoding it again turned the % itself into %25, so %20 became %2520. Use Decode once to get the original back, and only encode text that has not been encoded yet.

Is it safe to paste a URL here?

Yes. The tool runs entirely in your browser. Nothing you type is sent to a server, stored, or logged.

What does %2B mean in a query string?

It is an encoded plus sign. In a query string, a plain + is read as a space by many servers, so a real plus sign in your value has to be written as %2B to survive the trip.

What is the difference between %20 and + for a space?

In a query string both are read as a space by most servers, so q=hello+world and q=hello%20world usually mean the same thing. In a path, only %20 works: a + in a path is a literal plus sign. When in doubt, use %20, which is correct everywhere.

Can I decode a URL twice?

Only if it was encoded twice, which it should not have been. Decoding a normal encoded URL once gives you the plain text. Decoding it again can turn a real % sign in the original text into something else, or fail on a lone % with nothing after it. Decode once, check the result, and stop.
