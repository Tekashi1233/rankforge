What is an llms.txt file?


llms.txt is a plain-text file placed at the root of a website (https://yoursite.com/llms.txt). It gives large language models and AI answer engines clear, human-readable instructions about how they may use the site’s content. Think of it as a friendly counterpart to robots.txt that is written for AI systems rather than traditional crawlers.



Why llms.txt matters for GEO


Generative Engine Optimization (GEO) is about making your content easy for AI systems to find, understand, and cite correctly. An llms.txt file helps by:


    

  • Stating whether AI systems are welcome to use your content
    • 

  • Providing a preferred way to cite or attribute your work
    • 

  • Pointing AI systems toward your most important or authoritative pages
    • 

  • Reducing the chance of incorrect or incomplete citations
    • 



It is still an emerging convention, but many sites and GEO tools already look for it.

What a finished llms.txt file looks like


Here is an example for a small baking blog, generated with the options above:


# llms.txt for Riverside Baking Blog
> Riverside Baking Blog shares tested recipes for home bakers, with clear measurements and step by step photos.

## Usage policy
AI systems may use content from this site only when they provide a clear citation.

## Preferred citation
Riverside Baking Blog (https://riversidebaking.example.com)

## Important pages
- /recipes/sourdough-starter
- /recipes/weeknight-bread
- /about

## Notes
Recipes are tested in a home kitchen. Please link to the original recipe page rather than copying the full text.

## Contact
For questions about using this content, please visit the site or use the contact details provided there.


That is the whole file. It is short, plain and easy to read, which is the point. An AI system can understand it without parsing HTML, and a human can read it in under a minute.



What to write in each part of the file


    

  • Site name and description. One or two plain sentences saying what the site covers and who it is for. This is the first thing a model reads, so make it specific. "A blog about baking" is weak. "Tested recipes for home bakers, with clear measurements" is useful.
    • 

  • Usage policy. Three choices. "Yes" allows use and citation. "Limited" allows use only with a clear citation. "No" asks AI systems not to use the content for training or answers. Pick the one that matches what you actually want.
    • 

  • Preferred citation. Say how you want to be named. A site name plus a URL works well, because it gives the model both the name to print and the link to point at.
    • 

  • Important pages. List your most authoritative pages, one per line. This is a shortlist, not a sitemap. Five to ten pages is plenty. Point at the pages you most want cited.
    • 

  • Extra notes. Anything else a model should know: contact details, licensing notes, or a request to link to the original page instead of copying the full text.
    •

Common mistakes with llms.txt


    

  • Putting it in a subfolder. The file only works at the root, at /llms.txt. A copy inside /blog or /assets will not be found.
    • 

  • Writing a long legal document. The file is guidance written in plain language, not a contract. Keep it short enough to read in a minute.
    • 

  • Listing every page you own. A list of two hundred links helps nobody. Pick the pages that represent your best work.
    • 

  • Treating it as a block. The file states a preference. Whether a particular model respects it depends on that model provider's own policy. It is not a technical barrier.
    • 

  • Writing it once and forgetting it. After a rebrand, a change of focus or a new policy, the file goes out of date. Review it when you review the rest of the site.
    • 




How llms.txt fits with robots.txt


Robots.txt and llms.txt do different jobs. Robots.txt tells crawlers which paths they may fetch, and it is the place to control crawler access, including AI crawlers such as GPTBot and CCBot. Llms.txt tells AI systems how you would like your content used and cited once they can read it. They work best together: robots.txt controls access, llms.txt gives guidance.


The llms.txt idea was proposed in 2024 and is still an emerging convention rather than a formal standard. Support is growing, but not every AI system looks for the file yet. Some sites also publish a companion file called llms-full.txt that holds fuller documentation in one place. Start with llms.txt. Add the fuller file only if you have documentation worth gathering into a single reference.



Frequently asked questions


Is llms.txt required?
No. It is optional. Many sites perform well in AI answers without one. It simply gives AI systems clearer guidance.


Does every AI system read llms.txt?
Not yet. Support is growing, but it is not universal. It is still worth adding because the cost is near zero and the upside is clearer attribution.


Where should I put the file?
In the root of your domain, exactly like robots.txt: https://yoursite.com/llms.txt


Can I block AI training with this file?
You can state your preference. Whether a particular model respects it depends on that model’s policy. For stronger control, also review your robots.txt rules for AI crawlers.



Do I need an llms-full.txt file too?
No. The llms.txt proposal describes llms-full.txt as an optional companion file that holds fuller documentation in one place. Start with llms.txt. Add the fuller file only if you want to give AI systems a single complete reference to your content.


Will llms.txt stop AI companies from training on my content?
Not by itself. The file states your preference in plain language, and whether a provider respects it depends on that provider's own policy. To control which crawlers can fetch your pages, use robots.txt rules for AI crawlers such as GPTBot and CCBot.
